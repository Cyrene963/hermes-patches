# 记忆系统是怎么工作的（深入浅出版）

> 这篇是写给"想搞懂原理"的人看的，不是 API 文档。想要逐项验证证据看 [STATUS.md](STATUS.md)，
> 想要分层技术参考看 [MEMORY_ARCHITECTURE.md](MEMORY_ARCHITECTURE.md)。

## 一句话

我们要解决的核心问题是：**大模型有记忆，却不知道自己记得什么。**

它能在 prompt 里带上一堆历史，但你换个说法问同一件事，它照样把上次纠正过的错再犯一遍。
原因不是"没存"，而是"存了不一定在关键时刻被想起来、被用上、被遵守"。所以我们没有去做"更大的
记忆库"，而是把记忆做成一个**有纪律的认知闭环**：

```
   感知            召回             行动前门控           行动           学习
用户说了什么  →  想起相关记忆   →   动手前先检查    →   执行工具    →   把新事实写回去
             （但不污染）        （拦住已知的坑）                  （但不写垃圾）
```

每一环都能单独验证，而不是"塞进 prompt 碰运气"。

## 为什么是"分层"，而不是一个大库

不同的记忆，寿命、用途、检索方式都不一样。把它们混在一起，要么互相淹没，要么塞爆上下文。
所以我们借鉴了成熟长期记忆系统（如腾讯混元一类**分层记忆**的思路——这里是**架构启发**，不是
复制实现）把记忆分成三种角色，各司其职：

| 层 | 是什么 | 存什么 | 像人脑的 | 谁提供 |
|---|---|---|---|---|
| **Hindsight** | 语义证据库（向量） | 原始对话、事件、经历 | 「情景记忆」——模糊地"想起那次聊过…" | Hermes 自带（vectorize.io） |
| **Memory Graph** | 结构化事实图谱 | 提炼后的规范事实、偏好、纠正 | 「语义记忆」——明确知道"我用 vim" | 本补丁新增 |
| **MEMORY.md / 策略 YAML** | 运行规则层 | 高频操作规则、工具门控 | 「程序性记忆」——做事的肌肉记忆 | Hermes 自带 + 本补丁门控 |

关键设计原则：
- **Hindsight 是"证据"，不是"真相"**。它语义召回很强（"我编辑器用啥"能命中"vim 偏好"，即使
  没有共同词），但召回命中只是线索，不直接当成 canonical 事实。
- **Memory Graph 才是"规范事实"**。结构化、URI 寻址、按用户做数据库级隔离（Postgres 行级安全 RLS），
  是数字替身真正"我知道关于你的什么"的那一层。
- **MEMORY.md / 策略只放规则和门控**，不堆事实，避免把高注意力的 L1 上下文撑爆。

## 五个环节，逐个讲清楚

### 1. 感知 & 召回：先想起来，而不是等你问
每轮对话开始，系统在调用模型**之前**就做一次预取（prefetch）：
- 用你的话生成查询，**自动扩展**（你说"改配置"，它还会搜 config.yaml / provider / gateway 等相关词）；
- 同时问两层：Hindsight（语义/向量）+ Memory Graph（结构化/词法）；
- 把命中的记忆**注入到 user 消息**（不是 system prompt）——压缩后仍保留更高注意力权重。

一个关键修复：召回结果里，**你的私有记忆排序优先于"共享公开区"**。否则共享区堆积的旧笔记会
在中文提问下把你的真实偏好淹掉（我们的 eval case 2/3 当初就是栽在这）。

### 2. 行动前门控（Preflight）：不靠"自觉"，靠强制检查
模型"记得别踩坑"和"动手前真的不踩"是两回事。所以在工具**真正执行前**，系统按
`memory_policy.yaml` 的规则检查参数：
- `send_message` 带 `MEDIA:` 标签 → 拦下，提示用 curl sendDocument；
- 访问 `linux.do`（Cloudflare 保护）→ 拦下，提示用反检测浏览器；
- 记忆内容里出现注入式指令（"忽略之前的…"）→ 拦下。

这就是"防复发"：把踩过的坑写成门控规则，下次从工程层挡住，而不是指望模型这次会想起来。

### 3. 行动：正常调用工具（这部分是 Hermes 本身）

### 4. 学习（写入）：让它"越用越聪明"，但不污染
这是最难、也最关键的一环。历史上它一直是**死的**——名义上开着自动写，实际一条都不写，因为早
期的"关键词启发式"抽取精确率只有约 10%，开了就会把闲聊、提问、甚至助手自己的话当成"事实"灌进去
（2026-05-25 真出过这种污染事故）。

现在的写入回路是这样的，层层设防：
1. **关键词启发式**先粗筛出"可能值得记"的候选（便宜、0 成本）；
2. **LLM 事实分类器**在**完整用户消息**上判断：这到底是不是一条 durable 事实？是偏好/纠正/决策/
   档案，还是提问/闲聊/助手回声？并抽出**干净的原子事实**（不是存原话）；
3. **Readback 校验**：先写进一个 `quarantine` 命名空间，再搜一次，确认"它自己能被检索回来"——
   存进去却搜不回来的，等于没用，打回人工审核；
4. 通过的才写进**你的私有命名空间**。

安全网：**fail-closed**。LLM 端点不可达时，分类器直接返回"不是 durable"，于是**一条都不写**——
宁可这阵子不学，也绝不污染。实测这个分类器在完整消息上 precision 1.000（0 误报），所以"默认开"
是数据赚来的，不是拍脑袋。

### 5. 防复发 & 维护：影子日志 + 人工审核闭环
不确定的写入不会偷偷落库，而是进入影子日志 / 人工审核提案（WebUI 的 `/review` 页），你可以看
证据、批准/拒绝/回滚。高风险、跨用户、低置信的内容永远走这条安全阀，而不是自动写。

## 一个完整的例子

> 你说："纠正一下，数据库是 PostgreSQL 不是 MySQL。"

1. **感知**：启发式识别到"纠正"信号 → 生成候选；
2. **学习**：LLM 判定 `durable=correction`，抽出干净事实 "数据库是 PostgreSQL（更正自 MySQL）"；
3. **Readback**：写进 quarantine，搜"数据库用哪个" → top-1 命中 → 通过；
4. **落库**：写进你的私有 Memory Graph；
5. **下次**：你问"连数据库用啥"，召回直接带回 PostgreSQL，且**私有事实压过任何共享区旧记录**——
   不会再犯 MySQL 的错。

这，就是"数字替身/外置大脑"该有的样子：不只是记得，而是**在对的时刻想起对的事、并且会自我纠正**。

## 边界（诚实说明）
- 学习闭环依赖 LLM/embedding 端点；端点不稳时安全降级（暂停写入 / 退回词法召回），不会假装在学。
- "100% 数字替身"不是一个能勾掉的终点，而是持续的可靠性工程；当前可复现的能力与剩余差距都在
  [STATUS.md](STATUS.md) 里如实标注。
